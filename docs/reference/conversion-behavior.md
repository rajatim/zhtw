# 轉換行為與限制

## 保守轉換

ZHTW 的第一原則是「寧可少轉，不要錯轉」。沒有足夠語境時，工具可能刻意保留原文。這是安全邊界，不代表每個未轉字都是缺陷。

處理順序如下：

1. 以 leftmost-longest 規則選出較完整的詞彙。
2. identity rule 保護已正確或容易被子字串誤傷的內容。
3. 使用者明確選擇 `balanced` 時，才套用少量高信心歧義字預設。
4. 對剩餘位置套用安全的一對一字元對映。

## 來源地區

- `cn`：簡體字、中國常用詞與對應的台灣用語。
- `hk`：香港繁體用語轉台灣用語。
- `cn,hk`：CLI 預設，依固定順序合併兩種來源。

`source` 描述輸入文字的來源，不會改變輸出地區；輸出固定以台灣繁體中文為目標。

## Identity protection

Identity mapping 的 source 與 target 相同。它會佔住一段已正確文字，阻止較短規則在裡面再次轉換。這也用來維持 idempotency（重複轉換結果不變）。

## 已知限制

- 沒有句意模型；純文字規則無法理解所有人物、地名、雙關或專業語境。
- `strict` 不會猜測缺少語境的歧義字；`balanced` 仍只涵蓋有限集合。
- 自訂詞庫可覆蓋內建規則，呼叫端必須自行測試過度轉換風險。
- 一般文字模式會處理整段文字；結構化 JSON 必須明確啟用 adapter。
- benchmark 分數只代表指定版本、資料集與評分規則，不等於所有真實文本的保證。

要查單一結果，使用 `zhtw explain` 並參考 [Explain API](explain-api.md)。
